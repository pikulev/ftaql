# Обзор публичных API

FtaQl можно использовать через Rust API, CLI или WebAssembly. Выбор зависит от того, что вы анализируете: весь проект или один исходный файл.

| Вариант | Для чего подходит | Что принимает | Что возвращает | Ограничения |
| --- | --- | --- | --- | --- |
| Крейт `ftaql` и нативный CLI | Анализ проекта, CI, сравнение запусков | Путь к проекту и конфигурацию; CLI также принимает метаданные запуска | `FtaQlJsonOutput` в библиотеке; запись в SQLite и краткую сводку в CLI | CLI не печатает полный JSON |
| `@piklv/ftaql-cli` | Запуск CLI через npm или из JS/TS | Аргументы CLI или `runFtaQl(projectPath, options)` | Строку stdout нативного бинарника | Обёртка использует нативный движок |
| `@piklv/ftaql-wasm` | Анализ кода в браузере, песочницы, интеграции с редактором | Строку исходника, `use_tsx`, `include_comments` | JSON-строку одного `FileData` | Нет доступа к файловой системе и анализа межфайловых связей |

## Как выбрать вариант

- Если нужны анализ всего проекта, циклы зависимостей и история в SQLite, используйте нативный CLI или `@piklv/ftaql-cli`.
- Если вы встраиваете анализ в программу на Rust и хотите получить `FtaQlJsonOutput` в памяти, используйте Rust API.
- Если нужно анализировать отдельный файл в браузере, используйте WASM.

## Что учитывать при интеграции

Rust API и CLI используют общее ядро из `crates/ftaql`. Обёртка для Node.js запускает нативный бинарник синхронно через `execFileSync`, поэтому её вызов ждёт завершения анализа.

WASM получает только исходный код одного файла. Без контекста проекта он не вычисляет `coupling_metrics`, а имя файла в результате всегда равно `source.ts`.

Для анализа проекта настройки задаются в `ftaql.json`. Аргументы CLI позволяют указать путь к этому файлу, SQLite-базу и метаданные запуска. Дальнейшие шаги описаны в разделе [«Сценарии использования»](../usage-patterns/ru.md).
