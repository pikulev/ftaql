# Rust API и нативный CLI

Крейт `ftaql` предоставляет анализ всего проекта и отдельного модуля. Библиотечные функции возвращают структуры данных в памяти, а CLI сохраняет результаты анализа проекта в SQLite.

## Публичные точки входа

Крейт `ftaql` экспортирует:

- `analyze_project(path: &String, config: Option<FtaQlConfigResolved>) -> FtaQlJsonOutput`
- `analyze_module(module: &swc_ecma_ast::Module, file_name: &str, line_count: usize) -> FileData`
- `FileData::abs_path(project_root: &str) -> PathBuf`

## Что делает `analyze_project(...)`

Если нужно проанализировать проект на диске, вызовите `analyze_project(...)`. Функция последовательно:

1. Канонизирует путь проекта.
2. Обходит файлы через `ignore::WalkBuilder`.
3. Применяет `.gitignore` и исключения из конфигурации.
4. Разрешает импорты с учётом `tsconfig.json` и `jsconfig.json`.
5. Находит циклы полного графа и циклы зависимостей времени исполнения.
6. Вычисляет метрики файлов и собирает `FtaQlJsonOutput`.

## Что делает `analyze_module(...)`

Если вызывающая программа уже построила AST модуля, передайте его в `analyze_module(...)`. Функция вычислит `cyclomatic`, `halstead` и `file_score`.

Один модуль не даёт сведений о связях всего проекта. Поэтому в результате `coupling_metrics` всегда равен `None`, а `scores.coupling_score` — `0.0`. Смысл обеих оценок описан в разделе [«Скоринг»](../scoring/ru.md).

## Аргументы и результат CLI

CLI принимает:

- обязательный позиционный аргумент `project`
- обязательный `--db`
- опциональный `--config-path`
- опциональный `--revision`
- опциональный `--ref`

Если вы сохраняете несколько запусков в одну SQLite-базу, используйте параметры ревизии, чтобы различать результаты:

- `--revision` хранит точный идентификатор ревизии, обычно SHA коммита
- `--ref` хранит человекочитаемую метку ветки, тега или канала

Получив аргументы, CLI читает конфигурацию и запускает `analyze_project(...)`. Результат он сохраняет в SQLite через `persist_run(...)`, а в stdout печатает краткую сводку. Полная структура `FtaQlJsonOutput` в stdout не выводится.

## Важные нюансы

- `analyze_project(...)` принимает `&String`, а не `&str`.
- В коде анализа есть `expect()` и `unwrap()`, поэтому часть ошибок приводит к панике вместо возврата `Result`.
- Если `score_cap` превышен, `check_score_cap_breach(...)` завершает процесс через `std::process::exit(1)`.
- `CycleInfo.graph` хранит индексы в `project_analysis.cycle_members`, а не дублирует пути внутри каждого цикла.
