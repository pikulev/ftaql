# Конфигурация

## Где находится файл конфигурации

По умолчанию FtaQl ищет `ftaql.json` в корне анализируемого проекта. Если настройки лежат в другом месте, укажите путь через `--config-path`:

```bash
ftaql /path/to/project --db ./ftaql.sqlite --config-path ./ftaql.json
```

Если путь не указан и в корне проекта нет `ftaql.json`, FtaQl использует настройки по умолчанию. Если вы явно указали путь, а файла по нему нет, CLI завершится ошибкой.

## Поля и значения по умолчанию

Поля `includes` и `excludes` задают glob-паттерны: первые включают файлы в анализ, вторые исключают их. Файл `ftaql.json` поддерживает следующие настройки:

| Поле | Значение по умолчанию |
| --- | --- |
| `includes` | `**/*.js`, `**/*.jsx`, `**/*.ts`, `**/*.tsx` |
| `excludes` | `**/*.d.ts`, `**/*.min.js`, `**/*.bundle.js`, `dist/**`, `bin/**`, `build/**` |
| `score_cap` | `1000` |
| `include_comments` | `false` |
| `exclude_under` | `6` |

## Пример конфигурации

Чтобы анализировать TypeScript и TSX, задайте их шаблоны в `includes`. В этом примере `excludes` исключает декларации типов, каталог `dist` и корневой каталог `__tests__`:

```json
{
  "includes": ["**/*.ts", "**/*.tsx"],
  "excludes": ["**/*.d.ts", "dist/**", "__tests__/**"],
  "score_cap": 1000
}
```

## Как применяются настройки

Если `includes` или `excludes` указаны в файле, соответствующий список **полностью заменяет** значения по умолчанию. Чтобы сохранить стандартный список, не указывайте поле. Чтобы дополнить его, перечислите стандартные и новые шаблоны вместе. Пустой список `excludes: []` очищает настроенные исключения FtaQl; git-правила учитываются отдельно.

Поэтому пример выше сохраняет только три явно заданных исключения, а не весь стандартный список. Поля `score_cap`, `include_comments` и `exclude_under` также заменяют соответствующие значения по умолчанию.

После объединения настроек FtaQl сохраняет итоговую конфигурацию в SQLite, в поле `analysis_runs.config_json`.

## Исключение каталогов

По умолчанию `excludes` исключает файлы деклараций, минифицированные файлы, сборки bundle и каталоги `dist`, `bin` и `build`. При обходе проекта FtaQl дополнительно учитывает `.gitignore` и правила git exclude.

Поэтому `node_modules` часто пропускается благодаря git-правилам, хотя его нет в списке исключений FtaQl по умолчанию. Если нужный каталог не покрыт git-правилами, добавьте его glob-паттерн в `excludes`, сохранив остальные нужные исключения.

## Переход со старой конфигурации

Поля `extensions`, `exclude_filenames` и `exclude_directories` больше не читаются. Замените их на glob-паттерны в `includes` и `excludes`: например, `.ts` из `extensions` становится `**/*.ts` в `includes`, а `/dist` из `exclude_directories` — `dist/**` в `excludes`.

При переносе учитывайте замену списков целиком: старые настройки дополняли значения по умолчанию, а новые должны явно содержать все нужные шаблоны.

## Разрешение импортов

Чтобы определить, на какие файлы ссылаются импорты, FtaQl учитывает настройки `tsconfig.json` и `jsconfig.json`:

- `compilerOptions.paths`;
- `compilerOptions.baseUrl`;
- наследование через `extends`;
- ссылки между проектами (project references).

От разрешения импортов зависит, какие связи попадут в граф проекта и расчёт связности.

## Влияние настроек на результат

- `include_comments` меняет число строк `line_count`, которое участвует в расчёте `file_score`.
- Если `file_score` превышает `score_cap`, процесс завершается с кодом `1`.
- `exclude_under` сохраняется в конфигурации SQLite, но текущая реализация не использует это поле при обходе или фильтрации файлов.

Смысл и формулы `file_score` и `coupling_score` описаны в разделе [«Скоринг»](../scoring/ru.md).
