# Сценарии использования

Выбор API зависит от среды запуска и объёма анализа. CLI работает с проектом на диске, Rust API позволяет встроить анализ в приложение, а WASM принимает исходный код одного файла в браузере.

## Анализ проекта через CLI

Если нужно проанализировать проект локально или в CI/CD, используйте нативный CLI или `@piklv/ftaql-cli`. CLI сохраняет результаты каждого запуска в SQLite. Накопленные результаты позволяют сравнивать ревизии через SQL.

Порядок запуска описан в разделе [«CLI и API для Node.js»](../node-cli/ru.md), а формат сохранённых данных — в разделе [«Результаты в SQLite»](../sqlite-output/ru.md).

## Интеграция с приложением на Rust

Если анализ нужен внутри приложения на Rust, используйте крейт `ftaql`. Функция `analyze_project(...)` возвращает `FtaQlJsonOutput` в памяти. Если приложение уже построило AST модуля, передайте его в `analyze_module(...)` для расчёта метрик одного файла.

Сигнатуры и ограничения функций описаны в разделе [«Rust API и нативный CLI»](../rust-core/ru.md).

## Анализ файла в браузере

Если вы создаёте браузерную песочницу или интеграцию с редактором, используйте `@piklv/ftaql-wasm`. Пакет анализирует переданную строку исходного кода без доступа к файловой системе. Результат содержит метрики одного файла, поэтому для связей между файлами нужен анализ всего проекта через CLI или Rust API.

Пример вызова и формат результата описаны в разделе [«WebAssembly API»](../wasm/ru.md).
